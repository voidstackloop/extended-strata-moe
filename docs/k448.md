# Running Tessera-125B-MoE "k448" (Qwen3.8-Flash-Next, IQ2_S) on an 8 GB laptop GPU

Model: [`Voidstackloop/Tessera-125B-MoE`](https://huggingface.co/Voidstackloop/Tessera-125B-MoE), a 448-expert, IQ2_S/IQ4_NL GGUF of
Qwen3.8-Flash-Next (architecture `qwen4exp`, 70.5 GiB, 10 of 448 experts active). Its benchmark scores are on that page.
Everything here was measured on an RTX 4060 Laptop (8 GB), i7-13620H, DDR5-5200, 96 GB RAM, **native Windows** (clang-cl build), with no game running.

## Start it

`models/k448/windows/start-k448.bat` (128K context, port 8090) or `start-k448-fast.bat` (64K context + MTP draft, port 8091). Edit the model paths
at the top (`M`, `D`). Both use `--cpu-moe --moe-cache-hybrid --moe-cache-adaptive --moe-cache-lend` from this repo's patch.

| Profile | Context | MTP | Expert cache | Code answers | Prose / code explanations | Prompt |
|---|---:|---|---:|---:|---:|---:|
| `start-k448.bat` | 131,072 (q8_0 KV) | no | 950 MiB | 17 to 19 tok/s | 16 tok/s | 126 tok/s at 2.2K, 237 at 5.2K |
| `start-k448-fast.bat` | 65,536 (q8_0 KV) | 2 drafts | 600 MiB | 20 to 21.5 tok/s | 14.6 tok/s | 170 tok/s at 2.2K |

Short 300-token coding answers, greedy, server timings; one run per setting. A running game cut the speed by about a third (11.7 vs 17.5 tok/s).

## What the measurements say

* **The expert cache is the main lever.** With a 645 MiB cache (14% of expert lookups served from VRAM) decode was 17.5 tok/s; with 3.2 GB (52%) it was
  20 to 22.5 tok/s, using 7,947 of 8,188 MiB. The 128K context takes 1.8 GB of the card, so the 128K profile gets less cache.
* **MTP and a big cache do not fit together.** The draft model needs about 1.5 GB of VRAM; with a cache of 2.4 GB or more it fails to load
  ("invalid vector subscript"). Running the draft on the CPU instead gave no gain (21.6 tok/s).
* **MTP helps code, not prose.** Draft acceptance was 93% on code and 65% on explanations.
* **CPU expert math is not the limit.** `models/k448/bench/bench.c` times one-token expert matvec per quant type on the build's CPU backend:
  IQ2_S about 93 and IQ4_NL about 97 Gweights/s (IQ3_XXS only 65). An AVX-VNNI IQ2_S kernel was judged worth under 10% and not written.

## Claude Code and the chat template

Qwen3.8's template raises `System message must be at the beginning` for the system message Claude Code sends after the user turn (HTTP 500).
`models/k448/windows/make-k448-template.py` builds `k448-chat-template.jinja` from the model's own template, rendering a later system message in place as a
user turn; the start scripts pass it with `--chat-template-file`. No proxy is needed, and because the text stays at the same position the server's prompt
cache keeps matching between turns (an earlier proxy that folded it into the last user message made every turn re-read 1.5 to 2.6K tokens: a 133 s task
took 720 s). `test-k448-claude-shape.py` checks the request shape.

## Tools

`gen.py PORT [runs] [tokens]` (decode speed from the server's own timings), `gen_long.py PORT FILE [chars] [tokens]` (long prompt, run twice to see the prompt
cache), `bench.c` + `build.bat` + `run.bat` (CPU kernel speed). `models/k448/bench/RESULTS.md` has the raw tables.
